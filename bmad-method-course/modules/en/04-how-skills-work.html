How Skills Work

The SKILL.md architecture, step-file workflows, and why "just-in-time loading" prevents AI from hallucinating your project

A Skill Is a Named Workflow You Invoke by Name

In most AI tools, you describe what you want in plain language and hope for the best. In BMAD, you invoke a named skill that follows a precise, pre-designed process.

It's like the difference between telling a contractor "make my kitchen better" versus handing them a detailed renovation plan — room by room, task by task.

📄

SKILL.md

The top-level definition. Describes what the skill does, who should use it, and (for complex workflows) points to a workflow.md file for instructions.

🗺️

workflow.md

The orchestration layer. Defines the overall goal, the agent's role, and the rules for how steps are loaded and executed.

📋

step-01.md, step-02.md...

Each step is a self-contained micro-file. The agent loads only one at a time — never reads ahead — so it can't accidentally skip steps or blend instructions together.

Why this matters for you: You can see and edit these files. If you want to change how the PRD creation interview works, you edit the step files. BMAD is a transparent, hackable system — not a black box.

The "Just-In-Time" Trick That Prevents Hallucination

Here's a subtle but critical design choice: agents load step files one at a time, only when needed. This is called just-in-time loading.

FROM workflow.md 
## Core Principles

- Micro-file Design: Each step is a
  self contained instruction file
  that must be followed exactly

- Just-In-Time Loading: Only the
  current step file is in memory
  — never load future steps until
  told to do so

- Sequential Enforcement: Sequence
  within step files must be completed
  in order, no skipping allowed
PLAIN ENGLISH

Micro-file Design: Instead of one giant instruction document, each step of a workflow is in its own small file. Smaller = more focused = less room for the AI to get confused.

Just-In-Time Loading: The AI only reads the current step. It doesn't know what step 7 says while executing step 2. This prevents it from "skipping ahead" or letting future steps contaminate its thinking about the current one.

Sequential Enforcement: Steps happen in order. No optimization, no shortcuts. The structure is the quality guarantee.

Aha! moment: AI hallucination often happens because the AI has too much context at once and starts blending things together. By giving the agent only one step at a time, BMAD dramatically reduces the surface area where things can go wrong.

The Manifest: BMAD's GPS for Skills

How does the bmad-help skill know which skills exist, what order to use them in, and which ones are required? It reads a manifest file — a CSV that catalogs every installed skill with its phase, dependencies, and required status.

module-help.csv (excerpt) 
module,skill,phase,after,required

BMad Method,
  bmad-create-prd,
  2-planning,
  "",
  true

BMad Method,
  bmad-create-architecture,
  3-solutioning,
  bmad-create-prd,
  true

BMad Method,
  bmad-validate-prd,
  2-planning,
  bmad-create-prd,
  false
PLAIN ENGLISH

bmad-create-prd: Phase 2, no prerequisites, REQUIRED. You cannot meaningfully proceed to architecture without it.

bmad-create-architecture: Phase 3, must run AFTER the PRD is done, REQUIRED. The architect needs your requirements before designing a solution.

bmad-validate-prd: Phase 2, runs after PRD creation, NOT required. Useful for catching problems in complex projects, but you can skip it for a simple prototype.

The after column creates a dependency graph. When you ask bmad-help what to do next, it reads this manifest, checks which artifacts exist in your project folder, and deduces exactly where you are in the workflow.
