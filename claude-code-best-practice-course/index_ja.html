プログラマビリティ（適応性）による違い

Claudeと普通のチャットをすることは、ポケット電卓のようなものです。一つのことには優れていますが、毎回新しく設定し直さなければならず、あなたの要望や状態について全て毎回伝える必要があります。

対して Claude Code はプログラム可能なエクセルシートに似ています。同じ頭脳でも、独自のロジックの追加（コマンド）、外部データソースとの接続（MCPサーバー）が可能になり、毎回のセッションであなたの設定を記憶し続けます。

Claude とのチャット

プロジェクトを把握し、あなたのルールに従います。ワークフローを実行し、専門のエージェントを呼び出します（全て設定可能）。

02

コマンドとスキル

自動化の基礎用語 — レシピと知識用カートリッジ

コマンド：ワークフロー全体のショートカット

あなたがシェフだと想像してください。谁かが「リゾットを作って」と頼むたびに、リゾット全体のレシピをいちいち説明する代わりに、あなたはただ「リゾットを作って」と指示するだけです。レシピは既に書かれており、単にその名前を呼び出しているのです。

これがコマンドの役割です。これは、あなたが /its-name を入力したときに Claude が従う指示が満載された .md ファイルです。一度書けば、永遠に使えます。

📁
コマンドの置き場所

コマンドは、プロジェクトのルートにある .claude/commands/ の中に配置されます。各ファイルが / に続くスラッシュコマンドになります — 実行する際のコマンド名は、ファイル名になります。

コマンドの構造

これはリポジトリにある天気オーケストレーターという実際のコマンドです。一行ずつ読んでみましょう。

weather-orchestrator.md 
---
description: ドバイの天気を取得する
model: haiku
---

## ワークフロー (Workflow)

### ステップ 1: ユーザーに質問する
AskUserQuestionツールを使用して
摂氏か華氏かを尋ねる

### ステップ 2: 気象データの取得
Taskツールを使用して
weather-agentを呼び出す...

### ステップ 3: SVGカードの作成
Skillツールを使用して
weather-svg-creatorスキルを呼び出す。
わかりやすい解説

description: このコマンドが何を行うのかという概要を一行で。Claudeはこれを読み取り、いつ提案すべきかを判断します。

model: haiku — このコマンドには速くて安いモデルを使用します。コマンドごとにモデルを上書き・指定することができます。

ステップ 1 — 最初は、何かを行う前にユーザーに質問します。これにより、自動実行ワークフローが対話的な操作になります。

ステップ 2 — 専用のサブエージェント (weather-agent) を生成し、実際のデータを取得させます。コマンドが作業を指揮し、エージェントが作業を行います。

ステップ 3 — スキル (weather-svg-creator) を読み込み、視覚的な出力を生成します。各ステップを適切な専門機能に引き継がせます。

スキル：カセットのように差し込む拡張知識パッケージ

スキルとは、取り外し可能なメモリチップのようなものです。それには特定のタスクのための特別な知識、つまり特定のタスクの指示が含まれており、必要な時に Claude の記憶状態（コンテキスト）に読み込まれ、終わったらまた取り外されます。

ここでのポイントは、すべてを知っている巨大な一つの頭脳ではなく、スリムなメインフレームと、要求に応じて差し込むスキルファイルを持っているという点です。

📦

エージェント・スキル

03

サブエージェント (Subagents)

専用のツール、メモリ、自律制限を持った独立ワーカー

同僚ではなく、請負業者を雇う

同僚に助けを求める時、相手はあなたのプロジェクトすべてを知っています。会社の歴史も、作業内容も、規約もです。しかし、ときには代わりに請負業者（コントラクター）を雇いたいと思うことでしょう。

請負業者はやってきて、自分自身の機材で特定のタスクだけを完璧にこなし、そして帰ります。彼らに会社の全てを共有する必要はなく、単に手元のタスク情報だけを渡すだけです。これがサブエージェントという存在です。

🤝

メインの会話セッション

プロジェクトの全てを知っています。これまでの会話履歴を持ち、インタラクティブにあなたと作業します。

🏗️

サブエージェント

隔離されたコンテキスト。カスタムツールと権限、専用の設定。タスクを実行し結果のみを返します。他と並行して複数動かせます。

請負業者の事前設定

サブエージェントの設定は、上部ブロックのフロントマターで行います。これは実際の weather-agent のファイルです:

weather-agent.md (フロントマターの設定領域) 
---
name: weather-agent
description: Use PROACTIVELY when
  you need Dubai weather data.
model: sonnet
maxTurns: 5
permissionMode: acceptEdits
memory: project
color: green
skills:
  - weather-fetcher
---
解説

name: このワーカーを生成するために参照されるID名です。

description: "PROACTIVELY"（積極的に）というキーワードは、指定した条件・状況に合致したときにClaudeが自動的にこのエージェントの使用を提案・実行することを促します。

model: sonnet — このタスクの実行に使用する言語モデルの指定。コスト・精度の調整が行えます。

maxTurns: 5 — 最大5ターンのステップしか踏めないという自己制限。AIが暴走して延々とループすることを防ぎます。

permissionMode: acceptEdits — ここを設定すると、エージェントはあなたの承認なしにファイルの編集が自動的に可能になります。

memory: project — プロジェクトレベルの記憶領域（クロージャー）へのアクセス権限を明記します。

skills: weather-fetcher — 指定したスキルセットをエージェントに読み込ませます。

よく使う重要な設定項目

1つのエージェントには最大で16の設定項目がありますが、主に使用するのは以下の6つになります：

🎯

description (説明)

いつ起動するか。 "PROACTIVELY" などを設定し、自発的に起動させる文脈を記載。

🔧

tools (ツール許可一覧)

使用が許可されたツールの限定。 Bash(*) や Read など指定。

🛡️

permissionMode (権限モード)

編集の自動許可 acceptEdits や、計画の事後提示 plan、全権委任など。

🔢

maxTurns (最大実行ターン制限)

自動操作が止まらなくなる暴走シナリオを防ぐためのアクション制限。

🧠

memory (メモリ設定)

user、project、localなど、記憶領域のレベルを設定。

⚡

isolation: worktree (リポジトリの分離)

エージェントを現在のリポジトリとは別のコピー git worktree で動かします。リスクのある書き換え等にも安全です。

並列作業 (Parallel Agents) の仕組み

サブエージェントが生み出す強力な利点の一つは、タスクの並列性です。一つのコマンド指示から３つのエージェントが生み出され、独立したパーツをそれぞれ同時に分担していくことが可能です。

04

メモリと設定

Claudeにあなたの世界を教え、ガードレールを設定する

Claudeが毎朝読む従業員ハンドブック

新入社員は初日に会社のマニュアルを読みます。そこには、私たちが何をする会社で、どのように働き、何が許可され、何が禁止されているかが書かれています。毎日再教育する必要はありません—マニュアルの記述は記憶されます。

CLAUDE.md はあなたのプロジェクト用のClaudeのハンドブックです。これはプロジェクトのルートにあるMarkdownファイルです。Claudeは毎回のセッションの開始時にこれを読み込みます。ここに書き込んだものはすべて恒久的なコンテキストとなり、何度も再説明する必要がなくなります。

💡
CLAUDE.md には何を書くべきか？

プロジェクトのアーキテクチャ、コーディング規約、存在するコマンド、エージェントの役割、デバッグのヒント、コミットルールなど、新しくチームに入った開発者に伝えたいことなら何でも書きます。

メモリの3つの階層構造

CLAUDE.md ファイルは階層を形成しています。Claudeは最も広範なもの（グローバル）から最も特定的なもの（ローカルサブフォルダ）の順番で読み込みます。

🌍
グローバルメモリ

~/.claude/CLAUDE.md — マシンのすべてのプロジェクトに適用される個人的なルール。コードのスタイル、あなたの名前、希望する出力形式など。

📁
プロジェクトメモリ

./CLAUDE.md — この特定プロジェクトのルール。チーム全員とGit経由で共有される中核的な情報。

🔒
ローカルの上書き

./CLAUDE.local.md — プロジェクトに対する個人的な上書きルール。自分用のデバッグメモや秘密のプレファレンスで、Gitにはコミットしません。

許可ルール：あなたの安全柵

Claudeに許可する動作を正確に制御できます。権限システムには3つのモードがあります。allow（常に許可）、ask（確認を求める）、deny（完全にブロック）。

設定例 (.claude/settings.json):

.claude/settings.json (permissions) 
{
  "permissions": {
    "allow": [
      "Edit(*)",
      "Bash(*)"
    ],
    "ask": [
      "Bash(rm *)",
      "Bash(npm *)"
    ],
    "deny": []
  }
}
解説

allow: Edit(*), Bash(*) — Claudeは都度尋ねることなくファイル編集やコマンドを実行できます。* は任意の引数を意味するワイルドカードです。

ask: Bash(rm *) — 削除コマンドを実行する前には、必ず一時停止して確認を求めます。「自動」モード設定であっても保護されます。

ask: Bash(npm *) — パッケージのインストール等の操作には人間の承認を要求します。予期しない依存関係の追加を防げます。

フック（Hooks）：決してハルシネーションを起こさないロジック

これまで紹介したコマンド、エージェント、スキルなどは全てAIが駆動する要素です。しかし時には、確実で決定論的な動作が必要になることがあります。Claudeが作業を終えた時のサウンド通知、ファイル変更時のログ記録、ターミナルコマンド実行前のセキュリティチェックなどです。

これがフックの役割です。これらはAIの思考ループの「外側」で実行されるため、ハルシネーション（幻覚・嘘）を起こさず、プログラムされた通りに必ず実行されます。

MCPサーバー、オーケストレーションパターン、そしてパワームーブ

MCP: AIのためのUSBポート

初期状態でも、Claudeはファイルの読み書き、ターミナルコマンドの実行、URLのブラウジングなどを行うことができます。しかし、会社のデータベースを検索したり、ブラウザを高度に制御したり、社内APIを呼び出す必要がある場合はどうでしょうか？

そこで役立つのがMCP サーバーです。これはUSBポートのような役割を果たし、接続するだけでClaudeに新しい機能を与え、取り外せばその機能が消えます。

.mcp.json (実際の設定ファイル例) 
{
  "mcpServers": {

    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp"]
    },

    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    }
  }
}
解説

mcpServers — これによりClaudeへ外部機能接続を追加します。各エントリーは起動設定を持つ名前付きサーバー群です。

playwright — Claudeに実際のウェブブラウザを制御する能力を与えます。ボタンをクリックしたりスクレイピングなどが可能になります。

context7 — ドキュメントデータベースや外部情報などにアクセスするためのシステム連携機能。

全機能の連動：コマンド → エージェント → スキル
