Subagents

Autonomous workers with their own tools, memory, and limits

Hiring a contractor, not asking a colleague

When you ask a colleague for help, they know everything about your shared project — your history, your ongoing work, your conventions. But sometimes you want to hire a contractor instead.

A contractor shows up, does a specific job with their own tools, and leaves. They don't need to know everything about your company — just the task at hand. That's a subagent.

🤝

Main Session

Knows your whole project. Has your full conversation history. Works interactively with you.

🏗️

Subagent

Isolated context. Custom tools. Its own permission level. Runs a task and returns a result. Can run in parallel with others.

Configuring your contractor

You configure a subagent through frontmatter — a short block of settings at the top of the agent file. Here's the real weather-agent:

weather-agent.md (frontmatter) 
---
name: weather-agent
description: Use PROACTIVELY when
  you need Dubai weather data.
model: sonnet
maxTurns: 5
permissionMode: acceptEdits
memory: project
color: green
skills:
  - weather-fetcher
---
PLAIN ENGLISH

name: The ID Claude uses when another agent or command wants to spawn this worker.

description: PROACTIVELY — That keyword tells Claude to suggest or auto-use this agent when the situation calls for it.

model: sonnet — Use the smarter (but slower) model. You can tune this per-agent for cost vs. quality.

maxTurns: 5 — This agent is allowed to take at most 5 action steps. A safety guardrail so it can't spiral forever.

permissionMode: acceptEdits — The agent can edit files without asking you. Useful for automated workers.

memory: project — This agent can read and write to the project-level memory store between sessions.

skills: weather-fetcher — Load this skill into the agent's context from the start. The agent always knows how to call the weather API.

The fields that matter most

A subagent has 16 possible configuration fields. Here are the 6 you'll use in almost every agent:

🎯

description

Tells Claude when to invoke this agent. Add "PROACTIVELY" to make Claude auto-suggest it.

🔧

tools (allowedTools)

Exactly which tools this agent can use. Bash(*), Read, WebFetch(*), etc. Limits scope.

🛡️

permissionMode

acceptEdits — auto-approve edits. plan — show plan, don't act. bypassPermissions — full trust mode.

🔢

maxTurns

Maximum action steps before the agent stops. Your safety net against runaway automation.

🧠

memory

user, project, or local — determines what persistent memory this agent can access and write.

⚡

isolation: worktree

Runs the agent in its own git worktree — a separate branch copy. Safe for risky experiments.

Why parallel agents matter for you

If 3 research tasks each take 2 minutes, sequential execution takes 6 minutes. Parallel execution takes 2 minutes. When you tell Claude "do X, Y, and Z," understanding agents means you can ask for parallelism explicitly.
