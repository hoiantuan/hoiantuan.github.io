プログラマビリティ（適応性）による違い

Claudeと普通のチャットをすることは、ポケット電卓のようなものです。一つのことには優れていますが、毎回新しく設定し直さなければならず、あなたの要望や状態について全て毎回伝える必要があります。

対して Claude Code はプログラム可能なエクセルシートに似ています。同じ頭脳でも、独自のロジックの追加（コマンド）、外部データソースとの接続（MCPサーバー）が可能になり、毎回のセッションであなたの設定を記憶し続けます。

💬

Claude とのチャット

常に新しい会話からスタート。あなたのプロジェクトに関する記憶を持たないため、毎回全てを説明する必要があります。

⚡

Claude Code

プロジェクトを把握し、あなたのルールに従います。ワークフローを実行し、専門のエージェントを呼び出します（全て設定可能）。

あなたがコントロールできる６つの拡張機能

Claude Code には、動作をカスタマイズおよび拡張できる６つの要素が備わっています。このコースを通してそれぞれの使い方を学びます。

/
コマンド (Commands)

/slash-commands により起動される、再利用可能なタスクフロー

🤖
サブエージェント (Subagents)

カスタムツールとメモリを備えた、独立して動作する自律型アシスタント

📦
スキル (Skills)

特定の機能が必要な際に読み込まれる、知識のカートリッジパック

🔌
MCPサーバー (MCP Servers)

外部ツールやAPI、データベースとの接続レイヤー

🧠
メモリ (Memory)

CLAUDE.md ファイルを使用したプロジェクトの恒久的なコンテキスト維持

🪝
フック (Hooks)

AIの制御外のライフサイクルイベントで起動されるスクリプト

プロジェクトの恒久的な説明書

常に、Claudeがアクションを起こす前、Claudeはあなたの CLAUDE.md ファイルを読み込みます。これはわざわざ毎回説明する代わりに、一度だけプロジェクトに関する全体像を教えておく場所です。

リポジトリ側コードの例 
## 重要なコンポーネント

### 天気システム (Weather System)
以下が全体の動きを示すアーキテクチャ
Command → Agent → Skill
として連携しています。:
- `/weather-orchestrator`
  コマンド: 処理のエントリポイント
- `weather-agent`
  エージェント: 温度情報を取得
- `weather-fetcher`
  スキル: API通信の命令
わかりやすい解説

## 重要なコンポーネント — このセクションの見出しはClaudeに「ここにプロジェクトの大事な各部品がありますよ」ということを伝えています。

天気システム — コマンド、エージェント、スキルの全てがどのようにチームとして一緒に作業するかを示しています。

/weather-orchestrator — このスラッシュコマンドをあなたが打ち込むと、全ての処理プロセスが開始されます。

weather-agent — 実際のデータを引っ張ってくるためにClaudeが自律的に動かす独立した機能ワーカーです。

weather-fetcher skill — 天気APIの呼び出し方をエージェントに理解させるために事前に用意された再利用可能な知識セットです。

💡
アハ体験 (Aha Moment)

CLAUDE.md ファイルを使用することは、未来の自分のために付箋を残しておくようなものです。ただし、それを読むのはあなたではなくClaudeです。一度これを書いてしまえば、次回以降のすべてのセッションで、事前知識を持ってClaudeはサポートを開始してくれます。
