03

サブエージェント (Subagents)

専用のツール、メモリ、自律制限を持った独立ワーカー

同僚ではなく、請負業者を雇う

同僚に助けを求める時、相手はあなたのプロジェクトすべてを知っています。会社の歴史も、作業内容も、規約もです。しかし、ときには代わりに請負業者（コントラクター）を雇いたいと思うことでしょう。

請負業者はやってきて、自分自身の機材で特定のタスクだけを完璧にこなし、そして帰ります。彼らに会社の全てを共有する必要はなく、単に手元のタスク情報だけを渡すだけです。これがサブエージェントという存在です。

🤝

メインの会話セッション

プロジェクトの全てを知っています。これまでの会話履歴を持ち、インタラクティブにあなたと作業します。

🏗️

サブエージェント

隔離されたコンテキスト。カスタムツールと権限、専用の設定。タスクを実行し結果のみを返します。他と並行して複数動かせます。

請負業者の事前設定

サブエージェントの設定は、上部ブロックのフロントマターで行います。これは実際の weather-agent のファイルです:

weather-agent.md (フロントマターの設定領域) 
---
name: weather-agent
description: Use PROACTIVELY when
  you need Dubai weather data.
model: sonnet
maxTurns: 5
permissionMode: acceptEdits
memory: project
color: green
skills:
  - weather-fetcher
---
解説

name: このワーカーを生成するために参照されるID名です。

description: "PROACTIVELY"（積極的に）というキーワードは、指定した条件・状況に合致したときにClaudeが自動的にこのエージェントの使用を提案・実行することを促します。

model: sonnet — このタスクの実行に使用する言語モデルの指定。コスト・精度の調整が行えます。

maxTurns: 5 — 最大5ターンのステップしか踏めないという自己制限。AIが暴走して延々とループすることを防ぎます。

permissionMode: acceptEdits — ここを設定すると、エージェントはあなたの承認なしにファイルの編集が自動的に可能になります。

memory: project — プロジェクトレベルの記憶領域（クロージャー）へのアクセス権限を明記します。

skills: weather-fetcher — 指定したスキルセットをエージェントに読み込ませます。

よく使う重要な設定項目

1つのエージェントには最大で16の設定項目がありますが、主に使用するのは以下の6つになります：

🎯

description (説明)

いつ起動するか。 "PROACTIVELY" などを設定し、自発的に起動させる文脈を記載。

🔧

tools (ツール許可一覧)

使用が許可されたツールの限定。 Bash(*) や Read など指定。

🛡️

permissionMode (権限モード)

編集の自動許可 acceptEdits や、計画の事後提示 plan、全権委任など。

🔢

maxTurns (最大実行ターン制限)

自動操作が止まらなくなる暴走シナリオを防ぐためのアクション制限。

🧠

memory (メモリ設定)

user、project、localなど、記憶領域のレベルを設定。

⚡

isolation: worktree (リポジトリの分離)

エージェントを現在のリポジトリとは別のコピー git worktree で動かします。リスクのある書き換え等にも安全です。

並列作業 (Parallel Agents) の仕組み

サブエージェントが生み出す強力な利点の一つは、タスクの並列性です。一つのコマンド指示から３つのエージェントが生み出され、独立したパーツをそれぞれ同時に分担していくことが可能です。

🧑‍💼

再生ボタンでアニメーションを確認する
💡
なぜこの並列化が重要なのか

1つの調査タスクに2分かかるとします。３つあれば逐次処理で6分ですが、並列作業では2分で完了します。システムに「A、B、Cをやって」と頼む時、サブエージェントを使えば劇的な時間短縮が行えるのです。
